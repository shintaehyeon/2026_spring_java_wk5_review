# Spring Week 5 용어장 — 코드 보며 이해하고 암기하기

이 문서는 이 저장소의 **실제 파일을 읽을 때 필요한 말**을 정리했다. 먼저 [README의 전체 흐름](../README.md#1-전체-구조)을 보고, 모르는 단어가 나오면 여기서 찾는다. **읽기만 하고 끝내지 말고**, 아래 질문의 답을 보지 않고 말해본 뒤 브라우저에서 직접 확인한다.

## 1. 제일 먼저 외울 흐름

```text
브라우저 요청 → Controller → Service → Repository → DB
                                  ↓
브라우저 응답 ← HTML/JSON ← Controller ← 조회·처리 결과
```

| 말 | 한 문장 뜻 | 이 프로젝트에서 찾을 곳 |
|---|---|---|
| Java | 이 프로젝트의 코드를 작성한 언어 | `src/main/java` |
| Spring Boot | Spring 앱을 설정하고 실행하기 쉽게 만든 도구 | `Week5Application.java`의 `@SpringBootApplication` |
| Spring 컨테이너 | 필요한 객체(Bean)를 만들고 연결·관리하는 곳 | `BoardController`가 생성자로 `BoardService`를 받는 부분 |
| Bean | Spring 컨테이너가 관리하는 객체 | `@Controller`, `@Service`가 붙은 클래스의 객체 |
| MVC | Model(화면 데이터)·View(화면)·Controller(요청 처리)를 나누는 방식 | `PracticeController` → `Model` → `templates/practice/result.html` |
| Controller | 요청 URL을 받아 알맞은 작업을 시작하고 응답을 정함 | `controller/` |
| Service | 게시글 등록·수정 같은 처리 규칙을 담당 | `service/impl/BoardServiceImpl.java` |
| Repository | DB에 저장·조회 요청을 보냄 | `repository/BoardRepository.java` |
| Entity | DB 데이터와 연결되는 Java 객체 | `entity/Board.java` |
| DB | 데이터를 보관하는 곳 | 이 프로젝트는 H2 메모리 DB 사용 |

**외우는 문장:** “컨트롤러가 요청을 받고, 서비스가 처리하고, 리포지토리가 DB에 접근한다.” Entity는 이 단계들에서 다루는 **데이터의 모양**이다. 순서상 별도의 다음 단계가 아니다.

## 2. `Map`이란? `Model`과 뭐가 다른가?

### `Map` — 이름표(key)로 값을 찾는 Java 자료구조

`Map`은 **키(key) → 값(value)**의 짝을 저장한다. 예를 들어 `"sum" → 5`를 넣으면 `"sum"`이라는 이름으로 5를 꺼낼 수 있다.

```java
import java.util.HashMap;
import java.util.Map;

Map<String, Object> values = new HashMap<>();
values.put("a", 2);
values.put("b", 3);
values.put("sum", 5);
System.out.println(values.get("sum")); // 5
```

- `Map<String, Object>`: 키는 `String`, 값은 여러 종류를 담을 수 있는 `Object` 타입.
- `HashMap`: `Map`을 실제로 구현한 클래스. `new HashMap<>()`로 만든다.
- `put("sum", 5)`: 저장. 같은 키로 다시 `put`하면 앞의 값이 바뀐다.
- `get("sum")`: 그 키의 값을 가져온다. 없는 키면 `null`을 돌려준다.
- `HashMap`은 **넣은 순서대로 출력된다고 보장하지 않는다.**

이 프로젝트의 실행 코드에는 `Map` 변수를 일부러 쓰지 않았다. 더하기 화면은 `PracticeController.add()`에서 `Model`에 값을 **직접** 담는다. 아래는 수업에서 본 `Map` 방식과 비교하기 위한 *설명 예시*이며, 현재 파일에 그대로 들어 있는 코드는 아니다.

```java
Map<String, Object> values = new HashMap<>();
values.put("sum", a + b);
model.addAttribute("values", values);
// HTML(Thymeleaf)에서는 ${values.sum}으로 읽을 수 있다.
```

### `Model` — 컨트롤러가 HTML 화면으로 건네는 데이터

실제 [`PracticeController.add()`](../src/main/java/com/example/week5/controller/PracticeController.java)의 코드는 다음과 같다.

```java
model.addAttribute("result", a + b);
return "practice/result";
```

`Model`의 `"result"`는 화면에서 값을 찾을 이름이다. `return "practice/result"`는 `templates/practice/result.html`을 선택한다. 그 HTML의 `th:text="${result}"`가 합계를 표시한다. `Map`도 이름과 값을 저장하지만 **Java 자료구조**이고, `Model`은 **화면 템플릿에 데이터를 전달하는 Spring 객체**다. 둘은 관련은 있어도 같은 타입이 아니다.

### 이름이 비슷한 `.stream().map(...)`은 다른 뜻!

[`BoardRestController.list()`](../src/main/java/com/example/week5/controller/BoardRestController.java)에는 아래 코드가 있다.

```java
boardService.findAll().stream().map(BoardResponse::from).toList();
```

여기서 소문자 **`.map(...)`은 각 `Board`를 `BoardResponse`로 바꾸는 동작**이다. 키·값을 저장하는 대문자 **`Map` 자료구조와 다르다.** 영어 map에 “각 항목을 다른 형태로 대응시킨다”는 뜻도 있기 때문이다.

## 3. 요청과 응답을 읽는 말

| 용어 | 뜻 | 바로 확인할 예 |
|---|---|---|
| URL | 접속 주소 | `http://localhost:8081/practice/add?a=2&b=3` |
| `localhost` | 지금 내 컴퓨터 | 다른 사람의 인터넷 서버가 아니다. |
| 포트 `8081` | 내 컴퓨터에서 이 앱을 구분하는 번호 | `application.properties`의 `server.port=8081` |
| HTTP 요청 | 브라우저가 서버에 보내는 메시지 | “`/boards` 목록 주세요” |
| HTTP 응답 | 서버가 브라우저에 돌려주는 메시지 | HTML, JSON, 글자, 상태 코드 등 |
| Query parameter | `?` 뒤의 이름=값 | `?a=2&b=3`에서 a=2, b=3 |
| Path variable | URL 경로에 들어간 값 | `/practice/param/hello`에서 word=hello |
| Body | 요청/응답 메시지의 내용 부분 | POST JSON 본문, 결과 JSON 본문 |
| JSON | 데이터 교환에 쓰는 `{ "name": "값" }` 같은 형식 | `/api/boards` 응답 |
| HTML | 브라우저에 보여줄 페이지 형식 | `templates/board/list.html` |
| Thymeleaf | HTML에 서버 값을 끼워 넣는 템플릿 도구 | `th:text="${result}"` |
| REST API | URL·HTTP 방식으로 데이터를 주고받는 약속 | `/api/boards` |

`GET`은 조회, `POST`는 생성·제출, `PUT`은 전체 수정, `DELETE`는 삭제에 주로 쓴다. **주소창에 직접 주소를 입력하면 보통 GET 요청**이다. 그래서 REST의 POST·PUT·DELETE 확인에는 폼이나 API 도구가 필요하다. 이 프로젝트의 일반 HTML 폼은 브라우저 폼의 제약 때문에 수정·삭제도 POST로 보낸다. REST 컨트롤러는 PUT·DELETE를 따로 받는다.

## 4. 코드에 붙은 `@` 표시와 Java 용어

`@`로 시작하는 것은 **어노테이션**이다. “Spring/JPA가 이 코드를 어떻게 다룰지” 알려주는 표시라고 생각하면 된다.

| 코드 | 뜻 | 실제 위치 |
|---|---|---|
| `@SpringBootApplication` | Spring Boot 앱의 시작 설정 | `Week5Application.java` |
| `@Controller` | 주로 HTML 화면을 돌려주는 컨트롤러 | `PracticeController`, `BoardController` |
| `@RestController` | 메서드 반환값을 응답 본문으로 보내는 컨트롤러 | `PracticeRestController`, `BoardRestController` |
| `@ResponseBody` | 이 메서드의 반환값을 화면 이름 대신 응답 본문으로 보냄 | `PracticeController.test()` 등 |
| `@RequestMapping("/boards")` | 클래스의 공통 URL 앞부분 | `BoardController` |
| `@GetMapping` / `@PostMapping` | 해당 URL의 GET / POST 요청을 받음 | `controller/` |
| `@PathVariable` | 경로의 `{id}`·`{word}` 값을 받음 | `BoardController.detail()` 등 |
| `@RequestParam` | `?a=2`나 일반 폼의 파라미터를 받음 | `PracticeController.add()` 등 |
| `@RequestBody` | JSON 같은 요청 본문을 Java 객체로 받음 | `BoardRestController.create()` |
| `@Service` | 서비스 객체를 Spring이 관리하게 함 | `BoardServiceImpl` |
| `@Entity` | JPA가 DB 데이터로 관리할 클래스 | `Board` |
| `@Id` | 기본키(PK)로 사용할 필드 | `Board.id` |
| `@GeneratedValue` | 기본키 값을 생성하는 방식 지정 | `Board.id` |

**받는 방향과 보내는 방향:** `@RequestBody`는 **클라이언트 → 서버**의 내용을 받는다. `@ResponseBody`는 **서버 → 클라이언트**의 내용을 보낸다. `@RestController`에는 응답 본문으로 보내는 기능이 기본으로 들어 있다. 문자열은 글자로, 객체는 보통 JSON으로 응답된다.

| Java 말 | 한 줄 뜻 | 이 프로젝트의 예 |
|---|---|---|
| `package` | 클래스의 주소·소속 | `com.example.week5.controller` |
| `import` | 다른 패키지의 클래스를 사용하겠다는 선언 | `import org.springframework.ui.Model;` |
| `class` | 객체를 만들기 위한 설계 | `Board` |
| `interface` | 제공할 기능의 약속 | `BoardService`, `BoardRepository` |
| `implements` | 인터페이스의 약속을 실제로 구현 | `BoardServiceImpl implements BoardService` |
| `new` | 객체를 새로 만듦 | `new Board(title, content)` |
| 생성자 | 객체를 만들 때 필요한 값을 받는 메서드 | `BoardServiceImpl(BoardRepository boardRepository)` |
| `final` | 필드가 한 번 연결된 뒤 다른 객체로 재할당되지 않게 함 | `private final BoardRepository boardRepository;` |
| `List<Board>` | 순서가 있는 여러 `Board`를 담는 목록 | `BoardService.findAll()` |
| `Long` | 큰 정수를 담는 객체 타입 | `Board.id`, URL의 게시글 번호 |
| `record` | 데이터를 전달하는 클래스를 간결하게 선언하는 Java 문법 | `BoardRequest`, `BoardResponse` |
| DTO | 계층 사이에서 전달할 데이터를 담는 객체 | `BoardRequest`, `BoardResponse` |

### 생성자 주입을 한 문장으로

`BoardController`는 `BoardService`를 `new`로 직접 만들지 않고 생성자에서 받는다. Spring 컨테이너가 맞는 서비스 객체를 찾아 넣어준다. 이것이 **의존성 주입(DI)**이고, 여기서는 **생성자 주입** 방식이다. `@Autowired`를 필드에 붙이는 방식과 구분하자.

## 5. 저장·응답에 나오는 추가 용어

| 용어 | 이해할 뜻 | 코드에서 확인 |
|---|---|---|
| JPA | Java 객체를 DB와 연결해 저장·조회할 때 쓰는 규칙 | `@Entity`, `JpaRepository` |
| `JpaRepository<Board, Long>` | `Board`를 저장하고 `Long` ID로 찾는 저장소 인터페이스 | `BoardRepository.java` |
| PK(기본키) | DB의 각 행을 구별하는 고유 번호 | `Board.id`의 `@Id` |
| H2 메모리 DB | 연습용 임시 DB | 앱을 종료하면 게시글이 사라짐 |
| `application.properties` | 앱 설정 파일 | 포트·DB 주소 |
| `ResponseEntity<T>` | 응답의 상태·헤더·본문을 함께 정함 | REST 글 작성 시 201, 삭제 시 204 |
| HTTP 404 | 요청한 글이나 주소를 찾지 못함 | `BoardServiceImpl.findById()`의 예외 |
| `redirect:/boards` | 브라우저에게 `/boards`로 다시 이동하라고 응답 | 게시글 작성 후 |

`BoardRestController`의 `BoardResponse`는 **화면용 Model이 아니다.** REST 응답으로 보내는 데이터 모양이다. 같은 게시글도 페이지 컨트롤러는 HTML을, REST 컨트롤러는 JSON 데이터를 줄 수 있다.

## 7. 답을 가리고 말해보기 — 1분 암기 카드

| 질문 | 답 |
|---|---|
| Controller, Service, Repository는 각각 무엇을 하나? | 요청·응답 / 처리 규칙 / DB 접근 |
| Entity와 PK는? | DB 데이터의 Java 표현 / 각 행의 고유 식별자 |
| `Map`과 `Model`의 차이는? | Java 키·값 자료구조 / HTML 템플릿으로 데이터를 전달하는 Spring 객체 |
| `Map`과 `.stream().map()`은 같은 것인가? | 아니다. 후자는 각 항목을 다른 형태로 바꾸는 메서드다. |
| `?a=2&b=3`은 무엇으로 받나? | `@RequestParam` |
| `/boards/3`의 `3`은 무엇으로 받나? | `@PathVariable` |
| JSON 요청 본문을 받는 표시는? | `@RequestBody` |
| 반환값을 응답 본문으로 보내는 표시는? | `@ResponseBody` 또는 클래스의 `@RestController` |
| `return "board/list"`가 HTML 화면이 되는 조건은? | `@Controller`에서 화면 이름을 반환하고 해당 템플릿이 있을 때 |
| `BUILD SUCCESSFUL`이면 앱도 켜진 것인가? | 아니다. Run 창의 `Started Week5Application`을 별도로 확인한다. |

### 직접 확인하는 3가지

1. [`PracticeController.add()`](../src/main/java/com/example/week5/controller/PracticeController.java)의 `Model`에 담은 `result`가 [`result.html`](../src/main/resources/templates/practice/result.html)의 어디에 나타나는지 찾는다. 브라우저에서 `/practice/add?a=2&b=3`을 열어 **5**를 확인한다.
2. [`BoardRestController.list()`](../src/main/java/com/example/week5/controller/BoardRestController.java)의 `.map(BoardResponse::from)`을 찾아, 입력 타입과 출력 타입을 말한다.
3. `/boards`에서 게시글을 하나 만들고, [`BoardController`](../src/main/java/com/example/week5/controller/BoardController.java) → [`BoardServiceImpl`](../src/main/java/com/example/week5/service/impl/BoardServiceImpl.java) → [`BoardRepository`](../src/main/java/com/example/week5/repository/BoardRepository.java) 순서로 해당 메서드를 손가락으로 따라간다.

**암기 완료 기준:** 표를 읽지 않고 각 질문을 한 문장으로 설명하고, 3가지 확인을 직접 해볼 수 있으면 된다.
